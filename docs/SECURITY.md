# ข้อมูลและสิทธิ์การเข้าถึงของ Doctor Top CPD

## เว็บนี้ไม่มีรหัสผ่าน

เจ้าของขอเปิดให้เพื่อนใช้โดยไม่ต้องมีรหัส และอนุญาตให้ใช้ Gemini API เดิม การเข้าถึงจึงเป็น **สตูดิโอร่วม**: ผู้ที่เปิด URL สามารถใช้บริการสร้างเสียง ดูคลังเสียง/ประวัติ และดาวน์โหลดผลงานของสตูดิโอได้ ไม่มีบัญชีแยก โควตารายคน หรือพื้นที่ส่วนตัวของแต่ละผู้ใช้

ใช้เฉพาะเสียงที่เจ้าของเป็นผู้ใหญ่และให้ความยินยอมจริง รวมถึงบทและไฟล์ที่ยอมให้ผู้ใช้สตูดิโอร่วมกันเข้าถึง ไม่ใช้เก็บข้อมูลผู้ป่วยหรือข้อมูลลับ

## ขอบเขตที่แยกจากโปรเจกต์เดิม

- Doctor Top CPD มี Vercel project, private Blob และ `SESSION_SECRET` ของตนเอง เริ่มจากคลังว่าง
- ไม่คัดลอกเสียงตัวอย่าง ประโยคยินยอม โปรไฟล์เสียง ประวัติ หรือไฟล์ output จากสตูดิโอเดิม
- แม้ใช้ Google API project เดียวกัน แอปแสดงและใช้เฉพาะเสียงที่ลงทะเบียนไว้ใน installation นี้และเสียงมาตรฐานที่รองรับ ไม่เปิดรายการ Google voice profiles ทั้ง project และไม่รับ custom voice ID ที่ไม่อยู่ในคลังของแอป
- pending uploads ผูกกับ session ของเบราว์เซอร์เพื่อกันคลิปของอีก session ถูกนำมาสร้างเสียง แต่เสียงและผลงานที่บันทึกสำเร็จเป็นคลังร่วม

## ข้อมูลลับอยู่ฝั่ง server

`GEMINI_API_KEY`, `BLOB_READ_WRITE_TOKEN` และ `SESSION_SECRET` อยู่ใน Vercel Environment Variables หรือ `.env` ของ local ไม่อยู่ใน Git, frontend หรือ API response ค่า session secret ใช้ลงนามคุกกี้อัปโหลด ไม่ใช่รหัสผู้ใช้

Blob เป็น **Private** ที่ระดับ storage แอปเป็นผู้ส่งไฟล์ออกให้ผู้ใช้เว็บไซต์ จึงไม่ควรเข้าใจว่า private Blob ทำให้ข้อมูลที่แอปเปิดร่วมกันกลายเป็นความลับจากผู้มี URL

คลิปและบทที่ส่งสร้างเสียงถูกประมวลผลโดย Google ตรวจ [Gemini API terms](https://ai.google.dev/gemini-api/terms) และสถานะ Billing ของบัญชีที่เชื่อมก่อนใช้งานข้อมูลส่วนตัว การลบไฟล์ local/Blob ไม่ได้ลบโปรไฟล์เสียงที่ Google เก็บ ต้องจัดการแต่ละส่วนแยกกัน

## สิ่งที่ห้ามเผยแพร่ลง repo

- `.env` / `.env.*` ยกเว้น `.env.example` ซึ่งเป็นค่าว่างเท่านั้น
- `.vercel/`, `.migration/`, `ACCESS.md`, logs, artifacts และสำเนา environment
- `voices.json`, `samples/`, `out/`, `_mock/` และไฟล์เสียงทุกชนิด
- `.venv`, caches และไฟล์ build ที่มีข้อมูลส่วนตัว

`.gitignore` กันไฟล์ใหม่แต่ไม่ลบประวัติที่เคย commit ถ้าคีย์หลุด ให้ revoke/rotate ที่ผู้ให้บริการก่อน แล้วจัดการประวัติ Git ด้วย อย่าแก้เฉพาะ commit ล่าสุด

## ก่อน push หรือแจก ZIP

1. รัน `python3 scripts/check_release.py` (Windows ใช้ `py -3`)
2. ตรวจ `git status`, `git diff --cached` และประวัติ Git ก่อนเปิด public
3. ทำ ZIP จาก source ที่ commit แล้ว: `git archive --format=zip --output=../doctor-top-cpd.zip HEAD`
4. ตรวจรายการไฟล์และ `.env.example` ใน ZIP อีกครั้ง ไม่ ZIP ทั้งโฟลเดอร์ที่ใช้งานจริง

ตัวตรวจ release ช่วยค้นหา pattern/path ที่กำหนด ไม่ได้รับรองว่าไม่มีความลับทุกชนิด

`server.py` สำหรับ local ฟัง `127.0.0.1` เท่านั้น ไม่เปิดพอร์ต local หรือ tunnel สู่สาธารณะ ใช้ cloud app ตามคู่มือเมื่อจะใช้งานผ่านอินเทอร์เน็ต ระบบเก็บ same-origin write checks และข้อจำกัดไฟล์ไว้ แต่ไม่มีระบบป้องกันการใช้โควตาเกินรายบุคคล
